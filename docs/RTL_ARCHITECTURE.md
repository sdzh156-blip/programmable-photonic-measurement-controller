# PMC V2.1 RTL Architecture

## 1. Block diagram

```text
                         SoC / MCU
                            |
                           APB
                            |
                     +------v------+
                     |  apb_slave  |
                     +------|------+
                            |
                     +------v-------+
                     | photonic_csr |
                     | prog bank    |
                     +------|-------+
                            |
                   configuration snapshot
                            |
                 +----------v-----------+
                 |   phase_sequencer    |
                 | phase/frame index    |
                 | event priority       |
                 | fault-safe policy    |
                 +----+------------+----+
                      |            |
               +------v---+   +----v--------+
               | timing   |   | pulse_engine|
               | engine   |   | trigger     |
               +----------+   +-------------+

External READY/FAULT levels ---> sync2_level ---------+
Sensor frame DONE toggle ------> sync2_toggle_event --+--> sequencer

Measurement events ----------------------------------> irq_ctrl --> IRQ
```

## 2. `apb_slave.sv`

Responsibilities:
- APB ACCESS-phase detection;
- word-alignment checking;
- zero-wait `PREADY`;
- `PSLVERR` aggregation from alignment and CSR decode;
- simple internal CSR request interface.

No register semantics are implemented here.

## 3. `photonic_csr.sv`

Responsibilities:
- programming register bank;
- persistent `CTRL.ENABLE`;
- W1P `COMMAND.START/ABORT` pulse extraction;
- `DEVICE_STATUS` readback of synchronized READY/FAULT levels;
- status/readback mux;
- phase-table storage;
- sticky ERROR_STATUS with HW-set-over-W1C semantics;
- INT_STATUS/INT_ENABLE software access.

Separating COMMAND from CTRL avoids one-shot commands unintentionally rewriting persistent ENABLE state. Programming-bank writes remain legal while BUSY because the sequencer runs from its active snapshot.

## 4. `phase_sequencer.sv`

This is the application-specific control core.

Main flow:

```text
IDLE
  -> LOAD_PHASE
       DARK   -> SETTLE? -> WAIT_SENSOR_READY -> TRIGGER -> WAIT_FRAME
       SIGNAL -> WAIT_EXC_NOT_READY
               -> WAIT_EXC_READY
               -> SETTLE?
               -> WAIT_SENSOR_READY -> TRIGGER -> WAIT_FRAME
       WAIT    -> WAIT_ONLY? -> PHASE_ADVANCE

WAIT_FRAME -> next frame / PHASE_ADVANCE
PHASE_ADVANCE -> LOAD_PHASE / IDLE(done)
Any active state -> SAFE_EXIT on hard fault or software abort
```

Every SIGNAL phase explicitly re-arms excitation readiness: excitation is kept off until synchronized READY is observed low, then enable is asserted and a fresh READY-high is required. This closes the stale-READY boundary between adjacent SIGNAL phases.

Frame completion is consumed as a one-cycle local event generated by `sync2_toggle_event`; there is no DONE-level hold/ACK/clear state.

## 5. `timing_engine.sv`

One shared 32-bit countdown resource is used because the control flow waits on only one programmed timing condition at a time.

- `start_i` loads/reloads a new delay and has priority over the previous timer state;
- `stop_i` cancels the current timer;
- `done_o` asserts when the active count reaches its terminal cycle;
- the sequencer checks success before timeout, implementing deadline-success-wins semantics.

The same engine is reused for settle/wait, sensor READY timeout, frame timeout and excitation READY-low/READY-high timeout windows.

## 6. `pulse_engine.sv`

A dedicated 16-bit pulse-width engine generates the sensor trigger. Separating trigger generation from the sequencer makes width behavior independently testable and prevents the main FSM from manually counting pulse cycles.

## 7. `sync2_level.sv`

Standard two-flop synchronization is applied only to asynchronous **persistent level** inputs:
- sensor READY;
- sensor ERROR;
- excitation READY;
- excitation FAULT.

It is not used as a generic pulse catcher.

## 8. `sync2_toggle_event.sv`

Frame completion is represented by a source-domain toggle bit. The block:
1. synchronizes the toggle through `sync2_level`;
2. stores the previous synchronized value;
3. XORs current and previous synchronized values;
4. emits one destination-clock event pulse per observed toggle change.

```text
async toggle -> 2FF -> sync_toggle ----+
                         |              XOR -> frame_done_event
                         +-> delay FF --+
```

This follows the same event-CDC method used in the 2D-DMA project. It removes the previous one-cycle ACK return path and `WAIT_FRAME_CLEAR` state.

The source toggle must start from the documented reset baseline and must not toggle twice faster than the destination can observe distinct changes.

## 9. `irq_ctrl.sv`

Implements event-style interrupts:

```text
INT_STATUS_next = (INT_STATUS_old & ~SW_CLEAR) | HW_SET
IRQ = OR(INT_STATUS & INT_ENABLE)
```

Hardware set therefore wins over software W1C on the same edge.

## 10. Digital fault-safe boundary

The PMC provides synchronous digital fault-safe shutdown after synchronized fault detection:
- excitation forced OFF after termination/fault;
- trigger suppressed outside an active measurement or during synchronized hard fault;
- timing and trigger engines stopped on safe exit.

This is **not** a standalone physical laser-safety interlock because external fault detection crosses a synchronizer and therefore has clock-domain latency. Physical personnel/equipment safety must be implemented independently when required.
